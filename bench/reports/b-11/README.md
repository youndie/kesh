# B-11: resident memory against `used_memory` on the reference dataset

**Result: resident memory is 2.4 times `used_memory` once the server is idle, and 2.8 times at its
peak during the load; `used_memory` is 2.3 times the dataset's own bytes.** The same at an eighth and
a sixteenth of the dataset. Research D-10 records it; the container check (B-11's third criterion)
has to use the peak ratio.

## How it was taken

`bench/memory/ratio.sh <scale> [runs]`: a fresh kesh (release build, md5 `da89bd2d…`, 256 KiB allocator
pages), the reference dataset at `<scale>` generated by `kesh-dataset --seed 42` and loaded through
`redis-cli --pipe` — the protocol path, every key through the command table — then 45 s idle for the
collector's timer to run, then `INFO memory`'s `used_memory`, `DBSIZE`, and the process's `VmRSS`
and `VmHWM`.

On the build machine (WSL2, 16 GB), 2026-09-25, with 4.0–4.1 GB available and another session's
builds resident — not a measurement host (the bench service's quirks). A ratio of memory is less
exposed to that than a pause or a latency, but the absolute numbers are this host's. The full dataset
needs a host above 16 GB (B-22).

## What it means

- **The 2.4 is mostly the collector's schedule.** The runtime targets a heap twice the live set
  (`targetHeapUtilization = 0.5`, research §1.2; B-19 saw peak resident 2.2 times the live heap in its
  probe). If `used_memory` tracks the live heap, 2 of the 2.4 is that target, and the rest the
  runtime, the allocator's partly used pages and the per-thread pages. That `used_memory` tracks the
  live heap is a *hypothesis*; comparing it with the GC log's `alive` is the check.
- **The peak, 2.8, is what a container limit has to hold**: during a load the heap runs ahead of the
  collector. A `maxmemory` of M needs a limit above 2.8 M plus the process's base — at full scale,
  `used_memory` extrapolates to ~10 GB and resident memory to ~28 GB at peak (*arithmetic, not
  measured*), above B-19's ~17 GB for the bare probe: the server's structures are heavier than the
  probe's.
- **`used_memory` is 2.3 times the user bytes** — keys, entries, bucket arrays, per-member nodes. That
  is the estimate's own model (`MemoryModel`), not a measurement of the heap.
